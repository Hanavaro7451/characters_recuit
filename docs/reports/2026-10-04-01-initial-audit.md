### Замечания по приоритету

1. **P1 — ORM и миграция Character несовместимы.** `app/models/character.py:29`
   объявляет name/race/character_class, а `migrations/versions/c941a6b82d30_create_characters.py:19`
   не создаёт эти колонки. После миграции ORM-чтение/вставка Character потребует
   отсутствующие колонки. Направление: согласовать модель и миграционную схему,
   проверить пустую PostgreSQL и реальную запись/чтение. Статически подтверждено;
   это пока не дефект доступного character endpoint — таких endpoint ещё нет.
2. **P2 — readiness возвращает 500 при отказе подключения.** В
   `app/api/routes/health.py:31` перехватывается только SQLAlchemyError.
   Изолированный HTTP smoke воспроизвёл 500 при недоступном loopback-порте БД.
   Направление: определить обработку ошибок подключения драйвера и проверить 200/503
   на живой/недоступной тестовой БД. Liveness должен оставаться независимым от БД.
3. **P2 — длина username проверяется до нормализации.** `app/schemas/user.py:9`,
   `:12`, `:28`, `:30` и `app/core/usernames.py:6`: casefold может расширить строку.
   Probe UserCreate с 128 символами `ß` принял результат длиной 256 при лимите 255.
   Это нарушает согласованность с VARCHAR(255) и может приводить к ошибке сохранения.
   Направление: проверять ограничения канонического значения; добавить граничный тест.
   Ошибка БД/HTTP в этом сценарии не воспроизводилась.
4. **P2 — auth не завершён по ТЗ.** `app/api/routes/auth.py:11`,
   `app/core/security.py:26`: только access JWT; нет выхода/обновления сессии.
   Перед UI нужен выбранный единый контракт, без молчаливого перехода на cookies.
5. **P2 — повторное чтение приглашения отсутствует.** `app/api/routes/campaigns.py:21`,
   `:35`, `app/schemas/campaign.py:15`: после перезагрузки Master может получить код
   только через rotate, инвалидируя старый. Нужен согласованный Master-only read-контракт.
6. **P3 — API недостаточно удобен для UI.** `app/schemas/campaign.py:43` возвращает
   user_id без имени; общий CampaignResponse не содержит роль текущего пользователя.
   `app/main.py:32` не настраивает CORS. Для отдельного origin нужен ограниченный CORS;
   альтернатива — один origin через proxy. Отсутствие CORS само по себе не даёт утечку.
7. **P3 — эксплуатационные пробелы.** Нет CI, backup/restore инструкции и frontend
   контейнера; Compose использует bind mount и reload и предназначен для разработки.
8. **P2 — риск повторного upgrade после полного downgrade.**
   `migrations/versions/eec067041dd7_create_users_campaigns_and_memberships.py:108`
   удаляет таблицы, но сохраняет campaignstatus/campaignmemberrole enum-типы.
   Offline SQL подтвердил отсутствие DROP TYPE; сбой повторного upgrade на PostgreSQL
   пока не воспроизведён. Направление: проверить цикл upgrade/downgrade/upgrade
   отдельно от обязательной проверки первого развёртывания пустой БД.

Нереализованные функции из матрицы — объём оставшегося MVP, а не регрессии текущего кода.

### Решения от пользователя

До ближайшей стабилизации:

1. Принять предложенный объём следующей итерации или поставить первым иной сценарий.
2. Уточнить, применялась ли `c941a6b82d30` к какой-либо сохраняемой БД: это определяет,

3. Для интеграционных проверок обеспечить доступный Docker daemon либо отдельную

До UI/auth-этапа:

4. React + TypeScript + Vite (JSX/hooks) или Vue + TypeScript + Vite
   (шаблоны/single-file components). Выбор зависит от того, какой подход хочется
   изучать и поддерживать; библиотек форм/серверного состояния пока не фиксируем.
5. Access/refresh позволяет развить текущий JWT-модуль, но требует правил хранения,
   обновления и отзыва. Cookie-сессия удобна для браузерного приложения, но требует
   сессионного хранилища и CSRF-защиты. Определить выход и срок жизни сессии.
6. UI/API под одним origin через proxy или разные origins с точным CORS allowlist.
