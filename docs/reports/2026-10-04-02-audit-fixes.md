## Обоснование решений auth

Access остаётся подписанным JWT, refresh — случайным непрозрачным секретом.
Сервер хранит только SHA-256 хеш refresh: это высокоэнтропийный машинный секрет,
а пароли пользователей по-прежнему хешируются Argon2. Сессия связывает access `sid`
с пользователем и абсолютным сроком действия; проверка сессии на каждом запросе
позволяет немедленно отклонять access после logout без ожидания истечения JWT.
Это добавляет обращение к PostgreSQL, приемлемое для размера группы из ТЗ.

История хешей использованных refresh сохраняется для обнаружения replay.
Проверка/потребление refresh и выпуск следующего выполняются под блокировкой одной
строки сессии в транзакции. При двух одновременных refresh один может успеть получить
ответ, затем второй обнаружит replay и отзовёт семейство: клиенту потребуется login.
Поэтому клиент должен выполнять не более одного refresh одновременно и не повторять
его вслепую после неопределённого сетевого результата. Это осознанная строгая политика,
без окна повторного использования. Очистка истёкших сессий — будущая эксплуатационная
задача; бессрочный активный доступ после срока семьи не допускается.
