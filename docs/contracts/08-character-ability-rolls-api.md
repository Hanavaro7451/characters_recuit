# Контракт API однократной генерации, задание 08

Дата: 2026-10-13. Префикс путей — `/api/v1`. Контракт зафиксирован до
реализации. Набор бросков не назначает результаты характеристикам.

| Метод и путь | Запрос | Успех |
|---|---|---|
| `GET /campaigns/{campaign_id}/characters/{character_id}/ability-rolls` | Тела нет | 200, сохранённый `AbilityRollSetResponse` |
| `POST /campaigns/{campaign_id}/characters/{character_id}/ability-rolls` | Тела нет или `{}`; любые поля, включая кубики и seed, дают 422 | 201 при первой генерации, 200 при повторе; один и тот же сохранённый набор |

`campaign_id` и `character_id` — положительные целые. `AbilityRollSetResponse`:
`id`, `character_id`, `generated_at` (UTC ISO 8601), `results` — ровно шесть
элементов в порядке `position` 1–6. Элемент: `id` (устойчивый ID экземпляра),
`position`, `dice` (четыре целых 1–6 в порядке выпадения), `dropped_index`
(индекс одного отброшенного минимума, 0–3), `total` (сумма остальных трёх,
3–18). При равных минимумах отбрасывается первый. Одинаковые суммы имеют разные
`id`. `generated_at`, кубики, ID и суммы не меняются при повторном запросе.

Сервер генерирует весь набор и фиксирует его одной транзакцией. Уникальность
набора на персонажа обеспечивается PostgreSQL, а проверка состояния и запись
сериализуются блокировкой строки персонажа. Первый успешный POST увеличивает
`Character.version` ровно на 1, чтобы ранее прочитанный PATCH не затёр новое
состояние. Повторные POST и GET версию не меняют. PATCH имени или справочных
ссылок не удаляет набор. После смены состояния сохранённый набор читается GET;
POST доступен только владельцу DRAFT в активной кампании, даже если набор уже
существует.

## Ошибки

| Ситуация | Статус |
|---|---:|
| Нет или неверен access token | 401 |
| Не состоит в кампании, неверный ID кампании/персонажа, Player обращается к чужому персонажу | 404 |
| GET до генерации | 404, без создания набора |
| Master вызывает POST для персонажа своей кампании | 403 |
| POST для собственного персонажа не в DRAFT или в завершённой кампании | 409 |
| Некорректный ID или поля тела POST | 422 |

## Матрица доступа

| Операция | Владелец Player | Другой Player | Master своей кампании | Пользователь вне кампании |
|---|---|---|---|---|
| GET набора | Да, в любом состоянии кампании/персонажа | 404 | Да, в любом состоянии кампании/персонажа | 404 |
| POST при активной кампании и DRAFT | Да, первый или повторный | 404 | 403 | 404 |
| POST в других состояниях | 409 | 404 | 403 | 404 |

Ручек изменения, удаления и переброса нет. Приватные заметки в ответе
отсутствуют.
