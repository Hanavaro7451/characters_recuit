# Контракт API распределения характеристик, задание 09

Дата: 2026-10-13. Префикс `/api/v1`. Контракт зафиксирован до реализации и
дополняет [07](07-character-draft-api.md) и [08](08-character-ability-rolls-api.md).

| Метод и путь | Запрос | Успех |
|---|---|---|
| `GET /campaigns/{campaign_id}/characters/{character_id}/ability-distribution` | Без тела | 200, `AbilityDistributionResponse` |
| `PUT /campaigns/{campaign_id}/characters/{character_id}/ability-distribution` | Полный `AbilityDistributionSave` | 200, сохранённый `AbilityDistributionResponse` |

Оба ID пути — положительные целые. PUT полностью заменяет распределение и выбор;
частичного обновления нет. Пример запроса:

```json
{
  "expected_version": 2,
  "assignments": {
    "STR": 101, "DEX": 102, "CON": 103,
    "INT": 104, "WIS": 105, "CHA": 106
  },
  "bonus_choice": {
    "pattern": "plus_two_plus_one",
    "plus_two": "STR",
    "plus_one": "DEX"
  }
}
```

`expected_version` положителен. Ключи `assignments` — ровно STR/DEX/CON/INT/
WIS/CHA; значения — ID шести разных результатов сохранённого набора этого
персонажа. Равные суммы допустимы. `bonus_choice` обязателен и имеет форму:

- `{"pattern":"plus_two_plus_one","plus_two":"STR","plus_one":"DEX"}`:
  две разные цели из трёх разрешённых закреплённой предысторией;
- `{"pattern":"plus_one_each"}`: цели — все три характеристики закреплённой
  предыстории, клиент их не перечисляет.

Допустимы только варианты из флагов закреплённой версии предыстории. Итог не
выше 20. Неизвестные поля, клиентские суммы, итоги, модификаторы и источники
отклоняются.

Ответ: `character_id`, `character_version`, `has_rolls`,
`assignment_complete`, `bonus_complete`, `complete`, `bonus_choice`, `abilities`
из шести элементов в порядке STR/DEX/CON/INT/WIS/CHA. Элемент содержит
`ability`, `roll_result_id`, `base_value`, `bonus`, `bonus_source`, `total`,
`modifier`. При положительном бонусе `bonus_source` содержит
`type="background"`, `catalog_version_id`, `name` закреплённой предыстории;
при действующем бонусе 0 равен `null`. Сервер считает
`modifier=floor((total-10)/2)`. Производные значения не хранятся отдельно.

| Состояние | GET |
|---|---|
| До генерации | 200: `has_rolls=false`, полнота `false`, значения характеристик `null` |
| После генерации, до распределения | 200: `has_rolls=true`, полнота `false`, значения характеристик `null` |
| Распределено, выбор завершён | 200: все признаки полноты `true`, база, бонусы, итоги и модификаторы вычислены |
| Несовместимая новая предыстория или legacy без неё | 200: `assignment_complete=true`, `bonus_complete=false`, `bonus_choice=null`; ID и база сохранены, бонус/итог/модификатор `null` |

Отсутствие не кодируется нулём. При совместимой смене предыстории выбор
сохраняется, а эффекты пересчитываются по новой закреплённой версии.
`plus_two_plus_one` совместим, когда вариант разрешён и обе сохранённые цели
входят в новую тройку; `plus_one_each` — когда разрешён новой версией, его
целями становятся её три характеристики. Закрытие закреплённой версии для
нового выбора не отменяет эффекты.

Успешный PUT сохраняет всё одной транзакцией и атомарно увеличивает
`Character.version` на 1. Старая версия даёт 409 без изменений. GET версию не
меняет. PUT и PATCH персонажа сериализуются на строке Character; смена
предыстории и сброс несовместимого выбора атомарны. Броски остаются неизменны.

## Ошибки и матрица доступа

| Ситуация | Статус |
|---|---:|
| Нет/неверен access token | 401 |
| Нет членства, неверный ID, Player запрашивает чужого | 404 |
| Master вызывает PUT для персонажа своей кампании | 403 |
| PUT вне DRAFT/активной кампании, до генерации, без предыстории или со старой версией | 409 |
| Неверная форма, дубли/пропуски/чужие ID результатов, неверные цели/вариант, превышение 20 | 422 |

| Операция | Владелец Player | Другой Player | Master своей кампании | Вне кампании |
|---|---|---|---|---|
| GET | Да, включая архив/завершение | 404 | Да, включая архив/завершение | 404 |
| PUT для DRAFT в активной кампании | Да | 404 | 403 | 404 |

Ответ не содержит приватных заметок. Полнота характеристик не означает
готовность всего листа к отправке мастеру.
